<!-- sdlc:auto:start overview -->
This repository holds a two-app 'notes' product generated by the Quorq AI SDLC platform: an approved Angular 22 (Vite/Analog) frontend that renders its screens against seeded sample data, and a Flask 3.0 backend that implements a shared notes board (create/edit/delete/report) plus a grievance-contact endpoint, backed by SQLAlchemy models that default to a local SQLite file but are designed to point at PostgreSQL 16 (via docker-compose or DATABASE_URL) in real environments.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite/Angular 22 tooling)
- Python 3.12
- pip
- Docker and docker-compose (for the PostgreSQL 16 service)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd backend && pip install -r requirements.txt
3. (optional) docker-compose up -d db  # starts PostgreSQL 16 on localhost:5432, user/password/db = app/app/app
4. (optional) set DATABASE_URL to point the backend at Postgres instead of the default SQLite file (sqlite:///./app.db)
5. cd frontend && npm install
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one Flask blueprint per architecture component that owns endpoints (api.py, web_spa.py), with business logic factored into app/services/*
- Backend: SQLAlchemy models use typed Mapped[...] columns on a shared declarative Base (app/database.py)
- Backend: database is SQLite by default for zero-config local runs; set DATABASE_URL to switch to Postgres with no code changes
- Backend: linting/formatting via ruff (ruff.toml); tests via pytest with pythonpath=. so `import app` works from backend/
- Frontend: one component per approved screen under src/screens/, each paired with an adjacent *.component.spec.ts Vitest test
- Frontend: shared screen behavior (navigate, brand) composed via src/lib/screen-base.ts; shared UI/icons in src/lib/ui.ts and src/lib/icons.ts
- Frontend: brand tokens centralized in src/lib/brand.ts and src/index.css as CSS variables
- Frontend: all backend calls funnel through the apiFetch helper in src/lib/api.ts, which reads VITE_API_BASE_URL/VITE_API_SECRET_KEY and attaches a bearer token; screens currently still render seeded sample data rather than calling it
- Frontend: ESLint + Prettier enforced (eslint.config.js, .prettierrc); npm run lint is treated as a required gate
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the API fail with a CORS error in the browser | Ensure the backend's ALLOWED_ORIGINS env var includes the frontend origin (defaults to http://localhost:5173/127.0.0.1:5173 for npm run dev if unset) |
| Backend fails to connect to PostgreSQL | Start the database with `docker-compose up -d db` and set DATABASE_URL to match its app/app/app credentials on localhost:5432; otherwise the backend falls back to a local sqlite:///./app.db file |
| `pytest` from backend/ can't import `app` | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` applies, or invoke it there directly |
| Playwright e2e tests fail to launch a browser | Run `npm run test:e2e:install` once before `npm run test:e2e` to fetch Chromium |
| `gunicorn` command from the Dockerfile fails locally | Ensure you run it from backend/ with dependencies installed; the factory target is `app:create_app()`, matching backend/app/__init__.py |
<!-- sdlc:auto:end troubleshooting -->
