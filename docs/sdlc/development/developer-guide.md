<!-- sdlc:auto:start overview -->
This repository holds a simple shared notes board app generated by the Quorq AI SDLC platform: an Angular 22 (Vite/Analog) frontend with approved, reviewed screens, and a Flask 3.0 backend exposing a small REST API for notes CRUD/report actions and a grievance-contact endpoint. The frontend currently renders seeded sample data and is not yet wired to the backend's real endpoints. The backend defaults to a local SQLite database but is designed to point at PostgreSQL 16 (via `DATABASE_URL`) in other environments, matching the approved stack (Flask + Postgres + AWS).
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for Angular 22 / Vite tooling in frontend/)
- npm
- Python 3.12 (per backend/Dockerfile)
- pip
- Docker and Docker Compose (optional, for running PostgreSQL via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone <repo> && cd <repo>
2. cd frontend && npm install
3. cd ../backend && pip install -r requirements.txt
4. (optional) docker compose up -d db  # starts Postgres 16 on localhost:5432 if you want to use it instead of the default SQLite file
5. (optional) set DATABASE_URL to point the backend at Postgres instead of the default sqlite:///./app.db
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one Flask blueprint per architecture component that owns endpoints (app/routes/), with business logic kept in a separate services/ layer
- Backend models use SQLAlchemy 2.0 declarative style (Mapped[...], mapped_column) inheriting from a shared Base in app/database.py
- Backend defaults to SQLite locally and swaps to Postgres purely via the DATABASE_URL env var, with no other code changes needed
- Frontend: one component per approved screen under src/screens/, each paired with a co-located `*.component.spec.ts` unit test
- Frontend screens extend shared helpers from src/lib/screen-base.ts (navigate, brand) and use shared ui/icon components from src/lib/ui.ts and src/lib/icons.ts
- Frontend uses Angular's zoneless change detection (provideZonelessChangeDetection) bootstrapped in main.ts
- API calls funnel through the single apiFetch helper in src/lib/api.ts, which centralizes base URL, bearer auth, and error handling
- Brand styling is driven by CSS variables (src/index.css) and a brand token module (src/lib/brand.ts)
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend are blocked by CORS | Set ALLOWED_ORIGINS (comma-separated origins) when running the backend; without it, only http://localhost:5173 and http://127.0.0.1:5173 are allowed by default in app/__init__.py |
| `pytest` run from the repo root fails with `ModuleNotFoundError: app` | Run pytest from the backend/ directory, where pytest.ini sets pythonpath=. so the app package is importable |
| Playwright e2e tests fail to start the backend | Ensure Python deps are installed in backend/ (pip install -r requirements.txt) before running npm run test:e2e, since playwright.config.ts boots `python -m flask --app app run` from ../backend as part of its webServer |
| Backend data isn't persisted between runs / wrong database used | The backend defaults to a local SQLite file (sqlite:///./app.db) per app/database.py; set DATABASE_URL to point at the Postgres instance from docker-compose.yml (or another Postgres 16 instance) if persistent/shared data is needed |
